I want to design a terminal app running in a small size terminal (40x40), using the "textual" toolkit (python).
This app is called "explorer".
See API documentation here: https://textual.textualize.io/api/

The current directory contains a python virtual environment (j1939_venv).
Should any python new module be installed, please insert them in the pip-compile directory (in a dedicated .in file).
Then, by running the bash script 'setup-env' from pip-compile directory, the virtual environment will be updated.

This python app will be a tool to analyse live CAN J1939 data (read only - no need to send messages yet).
The python "script log_j1939.py" contains a code sample that show how to send, receive CAN messages.

The textual app will show:
- a header indicating the current mode
- a main screen with presenting the data for this mode
- a footer offering shortcuts to switch between mode.

Desired modes to implement:

1) "stats": This mode presents the CAN bus statistics:
- activity: messages per seconds over the last second, last 5 seconds and las 15 seconds
- number of unique devices on the bus: (identified from the first byte of the CAN messages EID)
- number of unique PGN (from the PGN field of the EID)

2) "messages": this mode shows a live list of the received CAN messages, sorted by EID.
- one EID per line: EID on the left, age on the right
- when selecting a specific EID, full information of the latest message of this type is shown (EID, PGN, SPNs and decoded values)

3) "live": this mode shows a live view of the current data on the CAN bus.


To decode CAN messages, a json file contains a dictionnary of PGN/SPN that are known and to be displayed in the app (in the "messages" mode or in the "live" mode).
This dictionnary is called 'J1939_dictionnary.json' (in the app directory).
For each element (PGN, SPN), this dictionnary contains "nicknames" and a boolean that indicates if the transported value is to be displayed.
